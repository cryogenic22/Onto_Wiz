Cost 1

Knowledge walks out the door

When a senior analyst leaves, months of internalized judgment go with them. The replacement rebuilds context for 2–4 weeks per engagement — pure lost productivity, repeated across the practice.

Cost 2

Agents invent what they don't know

Ask a generic agent "why did Brand X lose share?" and it confidently says "demand fell." A senior knows to evaluate safety and supply first, then access, then demand. Without that governed order, the agent is plausibly, dangerously wrong.

Cost 3

No provenance means no trust

An answer with no lineage is unauditable. "Searchable rubbish is still rubbish." For decisions worth millions, the firm cannot ship an oracle that can't show its work — and clients won't accept one.

Why the obvious fixes fail

"Just write more documentation" ›
Docs rot the moment they're written, aren't machine-consumable, carry no governance, and capture what without when-it-doesn't-apply. An agent can't reliably consume a 40-page methodology PDF — and nobody updates it.
"Just do RAG over our knowledge base" ›
Vector search retrieves the nearest text, not the governed, correct text. It surfaces drafts next to verified rules, competing definitions side by side, and stale slides as gospel — with no lifecycle gate and no proof the retrieved context actually improves the answer. Proactive interference, not domain intelligence.
"Just fine-tune a model on our decks" ›
Fine-tuning bakes knowledge into weights you can't version, govern, audit, or selectively expose to a client. You can't deprecate a wrong heuristic, can't show provenance, and you've now encoded your secret sauce into a model artifact that's hard to protect. Knowledge must stay data, not weights.

One factory. Four moving parts. Many consumers.

OntoWiz is a domain-intelligence factory: it mines candidates, elicits judgment through play, governs every change, compiles versioned packs, and serves them through one engine behind three doors.

A versioned, composable bundle of governed knowledge artifacts — heuristics, data quirks, playbooks, metric definitions, guardrails, eval cases — sliced from the domain graph and compiled into a signed, license-gated context layer. Gamified SME elicitation that feels like sparring, not data entry. The machine proposes first; the SME validates, ranks, corrects, red-teams. The context engine

CTX — governed context compiler

A governance + relevance gate runs in front of an LLM-as-router hydrator. Drafts and deprecated artifacts are never even offered to the agent. The agent gets a tiny directory of what it may ask for, then hydrates only the slice a query needs — ~3.9k tokens vs 92k stuffed — and always with safety/override layers included.

The delivery

Headless API + MCP

One runtime, three doors: direct library import for trusted in-house agents, REST for any-language consumers, and MCP for LLM-native agents and IDEs. No business logic in the adapters — get_context() runs the whole governed pipeline server-side and returns a trust envelope.

Every mutation is a Delta. Every artifact has a testable consequence. Every answer ships with provenance. That discipline is the difference between a knowledge base and domain intelligence.
Key features

Built for governance, trust, and defensible IP

Each capability maps to a real, tested subsystem in the platform — not a roadmap promise. Expand any feature to see how it works.

📚 Pack registry & versioning ›
A file-backed, cached, versioned catalog. For any pack: coverage, eval/agent-lift score, freshness, overlay stack, lineage, and a copy-paste install snippet. Version diff shows v1.2 → v1.3 as a knowledge-as-code diff — artifacts added/changed/removed plus the deltas and eval movement that justified the bump. An agent pins a version; the firm tracks the asset.
⚖️ Governance & the Delta lifecycle ›
Every change is a Delta: PROPOSED → APPROVED → MERGED, with blast-radius analysis, HITL routing, and a full audit ledger. Artifact lifecycle transitions (DRAFT → REVIEW → VERIFIED → ACTIVE) happen only as the effect of a merged Delta. Ungoverned or mismatched transitions raise a GovernanceError — enforced, not advisory.
✅ Eval gate + agent-lift ›
A pack only compiles if its EvalCase suite passes and the agent-lift benchmark (with-pack vs without-pack) clears threshold. EvalCase is a first-class artifact, so Forge rounds literally manufacture the test suite. The headline number — "is the pack worth anything?" — is measured on every compile, not asserted.
⛏️ Mining — candidates from artifacts ›
Hybrid extractors (pattern + LLM) mine decks, PDFs, DOCX, code, SQL and transcripts into candidate artifacts — every one a PROPOSED Delta, never auto-promoted. Duplicate clustering merges "the same concept seen in three decks" into one canonical artifact while preserving provenance from all sources. Extraction proposes; only governance promotes.
🔒 IP protection — the Tier A/B boundary ›
The single load-bearing rule, CI-enforced: Tier A never imports Tier B. The factory — mining, the Forge, the loops, the compiler — physically doesn't ship. Clients receive Tier-A wheels + signed, license-gated packs. Packs can be encrypted at rest and decrypted by a per-client key; the strongest mode is pure SaaS, where the client holds nothing but an endpoint. Architectural separation is ~90% of the protection, and it's free.
🔄 Closed feedback loops ›
Agents call get_context(); telemetry records which artifacts were used, hit/miss, and confidence. Corrections become PROPOSED Deltas and new EvalCases automatically; failed retrievals propose aliases; low-confidence answers flag artifacts. EWMA tracks per-artifact reliability. The target metric: one correction prevents a whole class of future errors.

SME experience & outcomes

It should feel like sparring, not data entry

The senior SME is the scarcest, most valuable input. The Forge is designed so they feel like they're challenging the machine and teaching juniors at scale — not running a hamster wheel for points.

STEP 01

The machine proposes first

No blank page. The steward pre-loads the weakest, highest-impact spots in the pack. The SME reacts to a draft — reaction is easier than recall.

STEP 02

Five minutes, five cards

Approve · rank · correct · add caveat · mark uncertain. Keyboard-driven, never more than five. Each card is one micro-mission.

STEP 03

See exactly what their click creates

Before they commit, the SME sees the three artifacts their judgment will produce — delta, eval, confidence. Knowledge production is the visible point.

STEP 04

Dissent is the highest status

"Everyone says X, but it fails when Y" scores higher than agreement. Useful, provable contrarianism gets its own badge.

STEP 05

Watch their judgment land

"Your call on the IQVIA lag is now live in the pack and blocks a known bad answer." That sight — not points — is the motivation engine.

ForgeRating — not points

A calibrated judgment rating

Think chess Elo for domain judgment. It only moves on things that improve the firm's brain, and it's computed, never awarded for activity.

  • Correctness — agreement with eventual consensus / gold outcome
  • Novelty — created a new artifact vs confirmed an existing one
  • Impact — blast radius × downstream agent usage
  • Eval value — produced a gold EvalCase that catches a real error
  • Dissent value — disagreement that changed the pack weighted highest

Anti-gaming: consensus-weighted, contributions decay if unused, and identical rapid clicks are ignored — not rewarded.
