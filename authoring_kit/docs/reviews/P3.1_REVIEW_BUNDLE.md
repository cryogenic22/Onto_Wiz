## 1. Mini-spec / design

The keyless **`AuthorityHostClient`** implements the nine-method `AuthoringTrustProvider` protocol
(`authoring.py:408-463`) as an out-of-process proxy over **authenticated local IPC**, so the kernel can call
provider methods during authoring while all trust stays external. Design:

- **Wire protocol** (`authority_client.py`): a versioned (`PROTOCOL_VERSION=1`), length-bounded, strict,
  redacted request/response envelope — one method per exchange. Canonical NFC JSON; duplicate-key and
  non-finite constants rejected both directions. The **allowlist** is the eight authoring methods +
  `issue_credential`; `advance_authority` is **not** on it.
- **Transport** (`LocalIpcTransport`): `multiprocessing.connection` over a **Windows named pipe**
  (`AF_PIPE`) / **POSIX UDS** (`AF_UNIX`); the `authkey` performs a bidirectional HMAC challenge (host
  authenticates client; client authenticates host = the server pin). One connection per exchange. **No
  HTTPS** (out of P3).
- **Protected config** (`ProtectedConfig` + `resolve_protected_config`): endpoint / family / version /
  provider id / server pin / limits / timeout, from an admin-owned location. The **workspace never supplies
  the endpoint**; **no TOFU**; a missing/unreadable/version-mismatched config, or (POSIX) a
  drafting-writable one, fails closed to `AuthorityTransportError`.
- **Error taxonomy** (`authority_errors.py`, dependency-free): `AuthorityClientError` base (unrelated to any
  kernel error) → `AuthorityTransportError`, `AuthorityProtocolError`, `AuthorityAdministrationError`. A
  reachable-host application refusal raises `AuthorityHostRefusalError` (a plain `RuntimeError`, **not** an
  `AuthorityClientError`) so it maps to `E_AUTHORIZATION`, not `E_AUTHORITY_UNAVAILABLE`.

## 6. Adversarial self-review (builder — honest; INT does the authoritative pass)

**Checked / defended:**
- **Wire strictness:** version mismatch, oversized, duplicate-key, non-finite, unknown-method,
  correlation-id mismatch, malformed result → all rejected (`AuthorityProtocolError`); tested.
- **Redaction:** responses carry only the declared model JSON or `{code, message}`; the client surfaces its
  own `AuthorityProtocolError`, never host internals.
- **Keyless:** the client holds no signing/credential-minting key and no authority high-water; it cannot
  mint credentials or advance authority. The only secret it reads is the **channel** `authkey` from
  protected config — a transport secret, not an authority key.
- **Mutual auth:** wrong server pin fails both directions → `AuthorityTransportError`; tested.
- **advance_authority:** triple-guarded — client hard-refuse + off the wire allowlist + host rejects.
- **Code distinctness:** transport/config/protocol failures → `E_AUTHORITY_UNAVAILABLE`; a host application
  refusal → `E_AUTHORIZATION` (via `AuthorityHostRefusalError`, not an `AuthorityClientError`); tested.

**Honest limitations (deferred / documented, not hidden):**
1. **Server pin = shared symmetric secret.** `multiprocessing.connection`'s `authkey` gives mutual **HMAC**
   authentication of the channel, not asymmetric public-key pinning. It is a faithful *authenticated local
   IPC* demonstration; asymmetric server-pin verification belongs to the future HTTPS transport (out of P3).
2. **Config writability enforced on POSIX only.** `config_is_group_or_other_writable` uses `st_mode` bits;
   on Windows this signal is not meaningful, so the check is not enforced there (documented; the writable
   test is POSIX-only, consistent with the kit's existing Windows-privilege skips, R5). Missing/unreadable
   config still fails closed on all platforms.
3. **Survival coverage.** The `except AuthorityClientError: raise` pass-through is present at **all 9**
   provider-call wrap sites (inspectable). Tests exercise the read/snapshot path (hits the high-water and
   authoring-state sites) and the mutation entry; the deeper mutation-only sites share the identical
   pattern but are not each individually driven (would need a transport that fails mid-transaction).
4. **Reference host is test-only.** A real, service-identity-separated authority host lives outside this
   repo (out of P3); the demo/tests use the in-repo `ExternalTestProvider` behind the wire.
