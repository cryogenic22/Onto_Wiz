# D0.2 — LifecycleBadge (FE Loop 0) · §12.1 mini-spec

**Lane:** FE (builder) · **Loop:** 0 · **Unit DoD (§13):** *icon + label, not
colour-only; all true states represented.* · **Source of truth:** Prototype 9 `.b.*`
badges + canonical enums.

## 1. Objective and user-observable outcome
A single `LifecycleBadge` in the Foundry design system that renders every real
governance/gate state as an **icon + text label** (never colour-only), on foundry
tokens. Visible in `/ui` as a "Lifecycle & Gate" section: one badge per state, each
legible in greyscale. Every station (Queue, Packs, Forge, Dashboard) later consumes
this one component instead of ad-hoc coloured spans.

## 2. Preconditions and pinned contracts
- D0.1 tokens exist in the working tree (`src/ui/tokens.*`). D0.1 is submitted at SHA
  `8263575` (awaiting verdict); D0.2 depends only on its tokens, already present.
- **True states are sourced, not invented** (R-anti-bloat):
  - `ontowiz_spec.Lifecycle` = draft · review · verified · active · deprecated · archived
  - `ontowiz_core.DeltaStatus` = proposed · approved · rejected · merged
  - Gate outcomes (Prototype 9 `.b.pass/fail/warn`) = pass · fail · warn
- Dep `lucide-react@^0.563` (already approved, in `package.json`) supplies icons.

## 3. Files and ownership paths (all FE-owned)
- `frontend/src/ui/LifecycleBadge.tsx` — new component.
- `frontend/src/ui/LifecycleBadge.test.tsx` — new tests.
- `frontend/src/app/ui/page.tsx` — append a "Lifecycle & Gate" gallery section.
- (coverage `include` already covers `src/ui/**` + `src/app/ui/**` from D0.1.)

## 4. API / events / schema changes
No backend/OpenAPI/DB/generated-client impact. Component API only:
```ts
type LifecycleState =
  | 'draft' | 'review' | 'verified' | 'active' | 'deprecated' | 'archived'
  | 'proposed' | 'approved' | 'rejected' | 'merged'
  | 'pass' | 'fail' | 'warn';
interface LifecycleBadgeProps { state: LifecycleState; label?: string; className?: string }
```
`label` overrides the default text for context wording (Prototype 9 reuses one tone for
"PROPOSED"/"CANDIDATE"/"endorsed", one for "active"/"✓ ratified") — tone+icon fixed by
`state`, text overridable.

## 5. State machine and invariants
Presentational; holds no lifecycle logic and drives **no** transitions (Tier-A read-only
principle — R1 untouched). Invariants: (a) every `state` maps to exactly one {icon,
tone, default label}; (b) the text label is always rendered (colour is never the sole
signal); (c) the icon is decorative (`aria-hidden`) so the accessible name = the label.
Forbidden: inventing a state absent from the enums above; colour-only differentiation.

## 6. Threat and data-egress delta
None. Pure presentational component; no network, input, auth, storage or model calls.

## 7. Tests → acceptance criteria (1:1)
| Acceptance | Test |
|---|---|
| All 13 true states render with a visible text label | `LifecycleBadge.test.tsx` › renders label per state (table-driven) |

(Retry/concurrency/restart: N/A — stateless pure component; noted per template.)

## 8. Migration, rollback, recovery
No migration. Rollback = delete the two new files + revert the gallery section. The
legacy `components/ui/Badge.tsx` is untouched (its adoption is D0.4), so no consumer breaks.

## 9. Telemetry / operational failure behaviour
None (presentational). An unmapped `state` is unreachable via the TS union; defensive
default renders the raw state string as its own label rather than throwing.

## 10. Out of scope / residual risk
- Not wiring existing consumers onto `LifecycleBadge` (that's D0.4).
- Forge-specific labels (contested/candidate/ratified/endorsed) ride the `label`
  override over base tones; dedicated Forge states arrive with E2.
- Residual: icon name drift across lucide versions — guarded by `tsc`/`next build`.

## 11. Dependency change
None new. Uses already-approved `lucide-react`.
