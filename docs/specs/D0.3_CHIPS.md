# D0.3 — Attribution / Provenance / Layer chips (FE Loop 0) · §12.1 mini-spec

**Lane:** FE (builder) · **Loop:** 0 · **Unit DoD (§13):** *long names/locators
responsive; links keyboard-accessible.* · **Source of truth:** Prototype 9 `.chip`,
`.chip.src`, `.chip.unval`, `.tag`/`.tag.l*`, `.av`/`.av.*` families + the ontology
layer model (L1–L5).

## 1. Objective and user-observable outcome
Three foundry-token chips that every station later reuses instead of ad-hoc coloured
spans, each carrying **provenance on every object** (the Prototype 9 north-star):

- **`AttributionChip`** — *who* (a person): a decorative initials avatar + the name,
  with optional `✓` (validated-by) and calibration score (`· 0.9`).
- **`ProvenanceChip`** — *where it came from*: a monospace source-locator
  (`🎙 00:12:31 · R. Mehta`, `📊 slide 23`, `📄 §3.2`, `⛏ intake`, `⚒ forge`,
  `◎ studio`, `🎯 session`), an optional `unvalidated` warning tone, and an optional
  **deep-link** back to the source.
- **`LayerChip`** — *which ontology layer*: `L1 entity … L5 scenario`.

Visible in `/ui` as an "Attribution · Provenance · Layer" section. **Long
names/locators stay responsive** (truncate with full text on hover/`title`, no clip at
360px); **provenance links are keyboard-accessible** (native `<a>`, visible focus ring).

## 4. API / events / schema changes
No backend/OpenAPI/DB/generated-client impact. Component API only:
```ts
export const ONTOLOGY_LAYERS = ['L1','L2','L3','L4','L5'] as const;
export type OntologyLayer = (typeof ONTOLOGY_LAYERS)[number];

export const PROVENANCE_SOURCES =
  ['transcript','deck','doc','session','forge','studio','intake','eval'] as const;
export type ProvenanceSource = (typeof PROVENANCE_SOURCES)[number];

type AvatarTone = 'cyan' | 'info' | 'iris' | 'jade';

interface AttributionChipProps {
  name: string;               // "R. Mehta" — always rendered as text
  initials?: string;          // avatar initials; derived from name when omitted
  tone?: AvatarTone;          // avatar background only; default 'cyan'
  validated?: boolean;        // trailing decorative ✓ (validated-by marker)
  calibration?: number;       // trailing "· 0.9" text
  href?: string;              // optional link → native <a>, keyboard-focusable
  className?: string;
}
interface ProvenanceChipProps {
  source: ProvenanceSource;   // drives the leading decorative icon
  locator: string;            // "00:12:31 · R. Mehta" | "slide 23" | "§3.2" — always text
  href?: string;              // optional deep-link → native <a>, keyboard-focusable
  unvalidated?: boolean;      // molten .chip.unval tone + warning icon
  className?: string;
}
interface LayerChipProps {
  layer: OntologyLayer;       // L1..L5
  label?: string;             // override default (e.g. "L1 · Entities"); tone/layer fixed
  className?: string;
}
```

## 5. State machine and invariants
Presentational; hold no lifecycle logic and drive **no** transitions (Tier-A read-only,
R1 untouched). Invariants:
- (a) **Colour is never the sole signal.** The identifying *text* is always rendered —
  the attribution name, the provenance locator, the layer label — independent of tone;
  the avatar and source/warning icons are decorative (`aria-hidden`), so a greyscale or
  colour-blind reader loses nothing.
- (b) **Long values are responsive, not clipped.** The name/locator truncates within a
  bounded flex child (`min-w-0 … truncate`) and exposes the full value via `title`; the
  chip never forces horizontal overflow at 360px.
- (c) **A link is a real link.** When `href` is set the chip renders a native `<a href>`
  (keyboard-focusable, `focus-visible` ring); otherwise a `<span>` with no link role.
- (d) Every `layer`/`source` maps to exactly one {default label / icon, tone}.
Forbidden: inventing a layer or source absent from §2; colour-only differentiation;
`div`/`onClick` faux-links (keyboard-inaccessible).

## 6. Threat and data-egress delta
None. Pure presentational components; no network, input, auth, storage, or model calls.
`href` is caller-supplied and rendered verbatim on an `<a>` (no javascript: scheme
constructed here; callers pass in-app routes / source anchors).

## 8. Migration, rollback, recovery
No migration. Rollback = delete `chips.{tsx,test.tsx}` + the mini-spec + revert the
`page.tsx`/`ui.test.tsx` gallery-section edits. No existing consumer is rewired (that is
D0.4), so nothing breaks. `globals.css`/`vitest.config.ts` are untouched by D0.3.

## 9. Telemetry / operational failure behaviour
None (presentational). An out-of-union `layer`/`source` is unreachable via TS; the
component falls back defensively (renders the raw value / a neutral tone / a generic
icon) rather than throwing.

## 10. Out of scope / residual risk
- Not wiring existing consumers onto these chips (that is D0.4+).
- L2/L4/L5 share the neutral `.tag` tone (faithful to Prototype 9, which colours only
  `.tag.l1`/`.tag.l3`); distinct per-layer accents are deferred, label carries meaning.
- Curator dual-attribution (SME + curator amendment) is an E-tier concern; D0.3 ships a
  single-attribution chip, composable side-by-side by callers.
- lucide icon-name drift across versions — guarded by `tsc`/`next build` (icon names
  verified present at `lucide-react@0.563.0`).

## 11. Dependency change
None new. Uses already-approved `lucide-react`.
