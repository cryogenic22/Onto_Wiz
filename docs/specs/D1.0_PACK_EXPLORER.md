# D1.0 — Pack Explorer vertical slice (FE Loop 1) · §12.1 mini-spec

**Lane:** FE (builder) · **Loop:** 1 · **Unit DoD:** *one screen driven by real
`ontowiz-serve` data, rendered entirely in D0 Foundry components, that surfaces the trust
envelope honestly — including the absence of evidence.* · **Source of truth:** the live
`ontowiz-serve` REST responses captured 2026-07-22 (§2), not a mock.

## 1. Objective and user-observable outcome
Close the integration gap named in the 2026-07-22 status read: the engine works and the
D0 component library works, but **no screen joins them** — `/control-plane` is fed by
`mock-data.ts` and D0.1–D0.4 have zero consumers. D1.0 ships `/packs`: a real-data screen
that lists compiled packs from `GET /v1/packs`, drills into one via
`GET /v1/packs/{n}/{v}/detail`, and probes it with `POST /v1/context` — showing the ranked
artifacts, the trust envelope, and the token estimate the engine actually returns.

The user-observable outcome is a screen you can drive against a running backend that makes
the **real** trust state legible, including the two gaps found in the live data (§5c).

## 2. Preconditions and pinned contracts
- Stacks on **D0.4** review SHA `e2460ec` (chain `5f2a4b5 → 8263575 → 5af28b1 → 59029aa →

- **The consumed contract is already `✅ VERIFIED`** (F3 `/v1/context`, F5 UX-2 `/detail`,

- Response shapes are **pinned from live capture**, not guessed:

          carries **no provenance field** at all. The first draft of this spec typed it as
          `extends PackSummary` with `sources`; re-reading the live response disproved both.
          `gaps` (served-but-untested artifact ids) was likewise missing from the draft.
  POST /v1/context        → ContextResponse { query, agent_type, system_prompt,

## 2a. Integration findings from the live run (added after the gates, 2026-07-22)
Two blockers were found by actually running the slice against the engine — neither was
visible from unit tests, which is the point of a vertical slice.

1. **`ontowiz-serve` ships no CORS middleware — BE-owned, still OPEN.** `OPTIONS
   /v1/context` → `405`, and `GET /v1/packs` with an `Origin` header returns no
   `Access-Control-Allow-Origin`. **No browser on a different origin can call the engine**,
   which would have blocked *any* frontend, not just this one. FE does not own server
   config, so D1.0 does not patch it; it routes around it with a Next `rewrites()` proxy so
   the browser talks same-origin and Next forwards server-side. This is also the better
   deployment shape: it keeps the backend origin **out of the client bundle** (`NEXT_PUBLIC_*`
   is inlined at BUILD time and cannot be changed at deploy time), reading the plain
   server-side `ONTOWIZ_API_ORIGIN` per request instead. **INT/BE should still decide
   whether the engine gets real CORS** — the proxy is a valid answer, not a workaround to
   be forgotten.
2. **Git-Bash mangles a leading-slash env var (cost a build cycle).** Running
   `NEXT_PUBLIC_ONTOWIZ_API_URL=/api/ontowiz npx next build` under Git Bash silently baked
   `"C:/Program Files/Git/api/ontowiz"` into the bundle via MSYS path conversion — the page
   then failed every fetch with no backend hit at all. Fix: `export MSYS_NO_PATHCONV=1
   MSYS2_ARG_CONV_EXCL='*'` before the build (or set the var from PowerShell). Same class
   of environment-specific trap as the Tailwind `source('../')` gotcha.

## 4. API / events / schema changes
**None.** D1.0 is a read-only consumer: three GET/POST calls against already-shipped,
already-verified endpoints. No backend, OpenAPI, DB, or migration impact. No endpoint shape
is proposed or altered — endpoint shapes are BE-owned and this unit does not touch them.

## 5. State machine and invariants
Container state is a 4-state machine per fetch — `idle → loading → (ready | error)` — with
an explicit `empty` terminal when the backend returns zero packs.

Invariants:
- (a) **No fabricated trust.** Every trust figure rendered is a field the API returned. The
  UI never computes, rounds up, defaults, or infers a confidence/lift/pass-rate.
- (b) **Absence of evidence is rendered, not hidden.** This is the load-bearing invariant.
  When `evals.eval_cases === 0` the card shows an explicit **"no eval evidence"** state — it
  must NOT fall back to a blank, a zero, or a passing tone.
- (c) **The live data makes (b) real, today.** Captured 2026-07-22:
  `commercial_analytics@0.1.0` carries `agent_lift 0.308 / 26 cases / gate_passed true`,
  but **`@0.3.0` — the latest — carries `eval_cases 0, agent_lift null, gate_passed false`**,
  and every artifact returns `sources: []`, `has_eval: false`, `coverage: 0.0`. The screen
  must show the newest pack as unevidenced rather than inheriting 0.1.0's headline number.
- (d) **Provenance is not invented.** The detail endpoint returns *no* provenance field, so
  every artifact renders "no provenance recorded" and **no `ProvenanceChip` is emitted at
  all**. D0.3's chips stay unused here rather than being fed a plausible-looking guess.
- (d2) **The engine's own gap list is shown.** `gaps[]` (served-but-untested artifacts) is
  surfaced as a count + list; on the seeded packs this is *every* artifact, and the screen
  says so instead of implying eval coverage that `coverage: 0.0` contradicts.
- (e) **Foundry-only.** Every pixel comes from D0 components/tokens; no legacy palette, no
  `--cp-*` control-plane token, no new one-off styling.
- (f) **Read-only.** No mutation, no POST that changes state (`/v1/context` is a read that
  takes a body). R1's one pipe untouched.
Forbidden: rendering a lift/confidence the response did not contain; showing `gate_passed:
false` in a pass tone; silently swallowing a fetch error into an empty list.

## 6. Threat and data-egress delta
Read-only egress to one operator-configured backend — the same one `catalog.ts` already
calls, so **no new destination is introduced**. With the §2a proxy the browser egresses
only to its own origin; the single outbound hop is made server-side by Next to
`ONTOWIZ_API_ORIGIN`. That is a net *reduction* in client-side exposure: the backend origin
no longer ships inside the JS bundle. The rewrite is scoped to the `/api/ontowiz/` prefix
and forwards nothing else. Note the proxy is unauthenticated and will forward whatever it
receives, so it must not be pointed at a backend that is reachable-but-privileged; today's
three endpoints are public reads. No credentials are added: these three endpoints are unauthenticated
today, and the extracted `authHeaders` stays optional and unused here. No secret, token, or
PII enters the component tree; the query string typed by the user is sent to the local
backend only. No storage, no third party, no model call from the browser.

## 8. Migration, rollback, recovery
No data migration. Rollback = `git revert`; `/packs` is a new additive route with no
consumer, and the `http.ts` extraction reverts by restoring the two private helpers in
`catalog.ts`. Recovery from a down backend is the rendered error state + retry (§7), not a crash.

## 9. Telemetry / operational failure behaviour
No telemetry added. Failure behaviour is explicit and user-visible: network/5xx → typed
`ApiError` → error state carrying the status and a retry control. A malformed/partial
payload renders the fields that are present and the "no evidence" state for those that are
not — it never throws in render. The default base URL points at localhost, so a
misconfigured deploy fails visibly and locally rather than silently reaching a wrong host.

## 10. Out of scope / residual risk
- `/v1/packs/{n}/{v}/explain` (lineage) is **not** wired in D1.0 — it belongs with D0.14
  evidence/lineage per convergence §D.
- Does **not** touch `/control-plane`, `mock-data.ts`, or `mock-server.ts`; the prototype
  rebase remains D1.2 and stays mock-fed until then. This unit does not make it real.
- Does **not** replace `/catalog`; the two coexist until INT decides the merge.
- Residual: the pinned shapes are transcribed from a live capture, so a future BE change to
  these verified endpoints would break the screen — mitigated by typed errors + the client
  tests, not by a generated client (that arrives with F0.3A).
- No auth: if BE later puts these endpoints behind the catalog's JWT, D1.0 needs the token
  wired through the (already-present) optional `authHeaders`.

## 11. Dependency change
**None.** Zero new npm dependencies (ADR-006). Uses React, the D0 components, and the
platform `fetch`; tests stub `fetch` directly rather than adding MSW.
