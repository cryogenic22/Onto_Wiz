## 4. Anti-bloat gate (gate 1)
`catalog.ts` already held private `getJson`/`postJson` against **this same backend**. D1.0
did not write a second fetch wrapper: the helpers were extracted to `http.ts` (provenance
noted in-file, error-message formats preserved verbatim) and both clients import them.
`catalog.test.ts` guarded the move — **9/9 still green, unmodified**.

**Declared residual overlap (not silently duplicated):** `catalog.ts::fetchPackDetail` hits
the same `/detail` URL but returns `@/types/catalog`'s weaker shape (`evals` is an untyped
`Record<string, unknown>`; its `ArtifactRow` has no `confidence`). That shape structurally
cannot express the §5b "no eval evidence" invariant, so `packs.ts` types the response
accurately. Converging the two clients would change a return type consumed by `/catalog`'s
verified components — outside this unit's blast radius, flagged for INT.

## 8. Threat / data-egress delta
Read-only. With the proxy the browser egresses only to its own origin; the single outbound
hop is server-side to `ONTOWIZ_API_ORIGIN`, which also removes the backend origin from the
client bundle (a net reduction vs the `NEXT_PUBLIC_` absolute URL). Rewrite scoped to the
`/api/ontowiz/` prefix. No credentials, storage, third party, or model call. **Caveat for
INT:** the proxy is unauthenticated and forwards whatever it receives, so it must not be
pointed at a privileged backend; today's three endpoints are public reads.

## 9. Known limitations / residual risk
1. **`ontowiz-serve` ships no CORS middleware — BE-owned, OPEN.** `OPTIONS /v1/context` →
   405; no `Access-Control-Allow-Origin` on any response. **No browser on a different
   origin can call the engine at all** — this would have blocked any frontend. FE does not
   own server config, so D1.0 routes around it with the Next proxy. **INT/BE should still
   decide whether the engine gets real CORS**; the proxy is a legitimate answer, not a
   workaround to forget.
2. **Git-Bash mangles a leading-slash env var (cost a build cycle).**
   `NEXT_PUBLIC_ONTOWIZ_API_URL=/api/ontowiz npx next build` under Git Bash silently baked
   `"C:/Program Files/Git/api/ontowiz"` into the bundle via MSYS path conversion; every
   fetch then failed with *no* backend hit. Fix: `export MSYS_NO_PATHCONV=1
   MSYS2_ARG_CONV_EXCL='*'` (or build from PowerShell). Same class as the Tailwind
   `source('../')` trap.
3. **The in-browser render is NOT verified.** Chrome extension script injection timed out on
   every tab (screenshot, console, and page-text all failed or returned stale), so I could
   not confirm the React bundle executing live, and I am not claiming it. What *is* proven:
   135 jsdom tests over the real client, a clean production build with `/packs` prerendered,
   the live API matching every type, and the full proxy→engine path returning real data at
   the exact URL the client constructs. INT can close this by opening the URL in §11.
4. `/v1/packs/{n}/{v}/explain` (lineage) not wired — belongs with D0.14.
5. `/catalog` and `/control-plane` are untouched and unchanged in behaviour.
6. The pinned shapes come from a live capture, not a generated client; a BE change to these
   verified endpoints would break the screen. Typed errors limit the blast radius; the real
   fix is BE's F0.3A generated client.
7. If BE later puts these endpoints behind the catalog JWT, the token must be threaded
   through the (already-present, currently unused) optional `authHeaders`.

## 10. Spec corrections made during the red phase (recorded, not hidden)
The first draft of the mini-spec typed `PackDetail` as `extends PackSummary` with a
`sources` field. Re-reading the **live** response disproved both: detail returns only nine
keys (no `signed`/`author`/`domain`/`layers`/`compiled_at`) and `artifacts[]` carries **no
provenance field at all**; `gaps` was missing from the draft entirely. Types, tests and spec
were corrected before implementation. This is why §5d renders "no provenance recorded"
rather than feeding D0.3's chips a plausible-looking guess.

## 11. Reproducing the live demo
```bash
# terminal 1 — engine
python -m uvicorn ontowiz_serve.api:create_app --factory --host 127.0.0.1 --port 8080

# terminal 2 — frontend (NOTE the MSYS guard if you use Git Bash)
cd frontend
export MSYS_NO_PATHCONV=1 MSYS2_ARG_CONV_EXCL='*'
NEXT_PUBLIC_ONTOWIZ_API_URL=/api/ontowiz npx next build
ONTOWIZ_API_ORIGIN=http://127.0.0.1:8080 npx next start -p 3100

# then open http://localhost:3100/packs
```
